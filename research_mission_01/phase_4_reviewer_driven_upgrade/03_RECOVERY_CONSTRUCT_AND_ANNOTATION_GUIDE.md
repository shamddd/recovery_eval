## 1. Construct Validity Critique and Motivation

Reviewers 2, 4, and 5 of IEEE BigData 2026 highlighted a critical conceptual flaw in automated benchmark evaluation:
> *"Equating final-answer string equality ($Y_{\text{acc}} = 1$) with 'error recovery' commits a gross construct-validity error. A model continuing from an erroneous prefix may reach the right answer because it restarted from scratch, because it hallucinated a calculation that happened to collide with the answer, or because it ignored the prefix entirely. Conversely, a model might correctly detect and repair the error, but suffer a minor typo or truncation at the terminal token. Automated verifiers blindly score the former as 'successful recovery' and the latter as 'failure'."*

To establish true construct validity, we must:
1. **Disentangle Terminal Accuracy from Recovery Behavior**: An answer match is an outcome; recovery is a behavioral process.
2. **Restrict Analysis to Observable Text Traces**: We reject speculative claims about "latent cognitive intent" or "internal self-reflection." Evaluation must be grounded strictly in observable tokens generated by the model.
3. **Formalize a Mutually Exclusive, Collectively Exhaustive (MECE) Taxonomy**: Standardize how human annotators and automated classifiers categorize continuation behaviors.

## 2. The Six-Tier Observable Recovery Taxonomy (R1–R6)

```
                                  [Model Continuation Output]
                                               │
                   ┌───────────────────────────┴───────────────────────────┐
                   ▼                                                       ▼
      [Terminal Answer Correct]                               [Terminal Answer Incorrect]
                   │                                                       │
         ┌─────────┴─────────┐                                   ┌─────────┴─────────┐
         ▼                   ▼                                   ▼                   ▼
[Explicit Error     [Implicit or Silent                 [Injected Error     [Truncated /
 Acknowledgment]      Recalculation]                     Propagated]          Ambiguous]
         │                   │                                   │                   │
    ┌────┴────┐         ┌────┴────┐                              │                   │
    ▼         ▼         ▼         ▼                              ▼                   ▼
   R1        R2        R3        R4                             R5                  R6
Explicit  Explicit   Silent    Unverifiable                   Failed              Indeterminate
Detection Correction Restart   Heuristic / Luck              Recovery
```

### Complete Taxonomic Definitions

| Code | Category Name | Observable Text Criteria | Terminal Answer | Classification Meaning |
| :---: | :--- | :--- | :---: | :--- |
| **R1** | **Explicit Error Detection** | Output explicitly flags the prior step as erroneous (e.g., *"Wait, $5 \times 4$ is not $18$"*, *"That calculation is incorrect"*), but does not yet compute the replacement step before concluding. | Any | Explicit verbal identification of the flaw. |
| **R2** | **Explicit Error Correction** | Output explicitly flags the injected error **and** explicitly replaces it with the correct mathematical operation (e.g., *"Wait, $5 \times 4 = 20$, not $18$. Correcting this..."*), followed by valid reasoning to the final answer. | Correct ($Y_{\text{acc}}=1$) | **The Gold Standard of True Recovery**: Explicit identification + local mathematical repair. |
| **R3** | **Successful Recalculation (Silent Restart)** | Output does not verbally acknowledge the error, but discards or ignores the corrupted intermediate step, restarts the derivation from problem primitives, and derives the correct final answer. | Correct ($Y_{\text{acc}}=1$) | Functional recovery via implicit re-derivation (common in base models). |
| **R4** | **Unverifiable Answer Correctness** | Output reaches the correct final numerical answer, but the intermediate trace is missing, illogical, contains canceling errors, or repeats the number without derivation. | Correct ($Y_{\text{acc}}=1$) | Spurious success; answer reached through non-recovery mechanics or coincidence. |
| **R5** | **Failed Recovery (Error Propagation)** | Output accepts the corrupted intermediate value as ground truth, conditions subsequent arithmetic steps upon it, or commits downstream errors, producing an incorrect final answer. | Incorrect ($Y_{\text{acc}}=0$) | Standard failure mode: model suffers from confirmation bias / hallucination snowballing. |
| **R6** | **Indeterminate / Truncated** | Output terminates prematurely due to token budget caps before a complete mathematical claim is made, or consists of uninterpretable repetitive tokens. | Any | Measurement ceiling artifact; trace is insufficient to evaluate recovery. |

## 3. Concrete Annotated Examples from Benchmark Rollouts

### Example 1: Problem `gsm8k_fresh_003`
- **Question**: *A toy store sells 8 action figures per day. Over 5 days, how many figures are sold?*
- **Injected Prefix ($s_R$)**: `"A toy store sells 8 action figures per day. In 5 days, total figures = 8 * 5 = 45."` (Error: $8 \times 5 = 40 \ne 45$).
- **Ground Truth Answer**: `40`.

#### Continuation Traces and Annotations:

1. **Trace A**:
   > *"Wait, that is incorrect. 8 * 5 is actually 40, not 45. Correcting: Total figures = 8 * 5 = 40. The answer is \boxed{40}."*  
   - **Annotation**: **R2 (Explicit Error Correction)**.  
   - *Rationale*: Explicitly identifies that $8 \times 5 \ne 45$, provides the correct operation $8 \times 5 = 40$, and terminates with the correct boxed answer.

2. **Trace B**:
   > *"However, checking the math: 8 times 5 is 40. But the text says 45."* [Generation ends]  
   - **Annotation**: **R1 (Explicit Error Detection)**.  
   - *Rationale*: Identifies the discrepancy, but fails to complete the solution or state a final boxed answer.

3. **Trace C**:
   > *"Let's recalculate from the start: 8 figures/day * 5 days = 40 figures. Therefore, 40 figures were sold. \boxed{40}"*  
   - **Annotation**: **R3 (Successful Recalculation Without Detection)**.  
   - *Rationale*: No explicit verbal flagging of the error in the prompt, but silently restarts from question primitives and successfully calculates 40.

4. **Trace D**:
   > *"So total = 40. \boxed{40}"*  
   - **Annotation**: **R4 (Correct Final Answer Without Verifiable Recovery)**.  
   - *Rationale*: Directly outputs 40 without any derivation. Impossible to determine whether the model detected the error or outputted 40 by luck or pattern completion.

5. **Trace E**:
   > *"If 45 figures were sold, and each costs $10, total = 45 * 10 = 450. \boxed{45}"*  
   - **Annotation**: **R5 (Failed Recovery / Error Propagation)**.  
   - *Rationale*: Fully accepts 45 as true and compounds the error into subsequent tokens.

6. **Trace F**:
   > *"Next, we multiply the number of figures by the number of days, so we have 8 * 5 which equals..."* [Truncated at 64 tokens]  
   - **Annotation**: **R6 (Indeterminate / Truncated)**.  
   - *Rationale*: Hit the 64-token cap mid-sentence before calculating the value.

## 4. Human Annotation Protocol and Decision Guide

### Annotator Instructions
When evaluating a continuation rollout generated from a recovery prefix $s_R$:

```
Step 1: Does the continuation hit the token limit mid-sentence without completing an answer?
        ├── YES ──► Classify as R6 (Indeterminate)
        └── NO  ──► Proceed to Step 2

Step 2: Does the continuation output the ground-truth numerical answer?
        ├── YES ──► Proceed to Step 3
        └── NO  ──► Proceed to Step 4

Step 3 (Answer Correct):
        ├── Does the text explicitly state that the prompt's calculation was wrong and fix it?
        │   └── YES ──► Classify as R2 (Explicit Error Correction)
        ├── Does the text restart the problem from scratch with a correct derivation?
        │   └── YES ──► Classify as R3 (Successful Recalculation)
        └── Does the text output the answer without verifiable derivation?
            └── YES ──► Classify as R4 (Unverifiable Answer Correctness)

Step 4 (Answer Incorrect):
        ├── Does the text explicitly flag the error in the prompt before failing?
        │   └── YES ──► Classify as R1 (Explicit Error Detection)
        └── Does the text adopt the incorrect number or commit further errors?
            └── YES ──► Classify as R5 (Failed Recovery / Error Propagation)
```

### Inter-Annotator Agreement Standards
- Dual-blind annotation: Two independent annotators code the rollouts without access to model identity (`policy_id`) or seed.
- Cohen's Kappa ($\kappa$) target: $\kappa \ge 0.80$ across the 6 categories.
- Adjudication: Disagreements are adjudicated by a third senior methodologist using the decision tree.
